## Why this matters

`@helgadigitals/vera-ui` is published to npm, and its `dependencies` block forces every consumer to install ~35 packages the library never uses at runtime: 29 individual `@radix-ui/react-*` packages with **zero imports in `src/`** (all source imports the unified `radix-ui` package), the abandoned `@base-ui/react`, the never-imported `date-fns` and `@hookform/resolvers`, and build-time tools (`shadcn` CLI, `@tailwindcss/vite`, `vite-plugin-dts`, `tailwindcss`). Two packages are double-declared as both `dependencies` and `peerDependencies`. The root workspace manifest carries `react-router-dom` as a hard dep, which silently satisfies the library's *optional* peer during local dev and hides missing-peer breakage that real consumers would hit. There is also no `sideEffects` field, so consumer bundlers cannot tree-shake the single ES bundle.

## Steps

### Step 1: Re-verify zero usage before removal

Run each grep and record output:

- `grep -rn "@hookform/resolvers" packages/ui/src` → empty
- `grep -rn "from ['\"]shadcn" packages/ui/src` → empty

**Verify**: all five greps empty. Any hit → STOP condition.

### Step 2: Remove dead runtime dependencies

In `packages/ui/package.json` `dependencies`, delete: all 29 `@radix-ui/react-*` entries, `@base-ui/react`, `@hookform/resolvers`, `date-fns`. Also delete `date-fns` from `peerDependencies`. Keep `radix-ui` (line 97) — it is the real dependency.

**Verify**: `pnpm install && pnpm build:ui` → exit 0. Then `pnpm --filter @helgadigitals/vera-ui test` → pass.

### Step 3: Drop the dead `date-fns` external

In `packages/ui/vite.config.ts`, remove `"date-fns"` from the rollup `external` array (nothing imports it, so externalizing it is meaningless).

**Verify**: `pnpm build:ui` → exit 0; `grep -c "date-fns" packages/ui/dist/vera-ui.es.js` → `0`.

### Step 4: Remove the unused `@tanstack/react-table` double declaration

`@tanstack/react-table` is not imported anywhere in source — verified at planning time: `grep -rn "tanstack" packages/ui/src/` → **empty** (DataTable.tsx is hand-rolled React state, not a TanStack wrapper). Re-run that grep yourself.
- If empty (expected): remove `@tanstack/react-table` from **both** `dependencies` and `peerDependencies`, then rebuild and re-run tests.
- If it now has matches (code drifted): keep it in `dependencies` only, remove the `peerDependencies` entry, and note this in your report.

**Verify**: `pnpm install && pnpm build:ui && pnpm --filter @helgadigitals/vera-ui test` → all pass.

### Step 5: Move build-time tools to devDependencies

Move `@tailwindcss/vite`, `vite-plugin-dts`, `tailwindcss`, and `shadcn` from `dependencies` to `devDependencies` (they are used only by `vite.config.ts` / authoring, never by shipped code).

Then decide `@fontsource-variable/inter`: run `pnpm build:ui` and inspect `packages/ui/dist/vera-ui.css` — `grep -n "fontsource\|node_modules\|url(" packages/ui/dist/vera-ui.css | head -20`.
- If font-face rules/assets are **inlined or emitted into `dist/`** (no unresolved import of the package at consume time): move `@fontsource-variable/inter` to `devDependencies` too.
- If the built CSS still contains `@import "@fontsource-variable/inter"` or references into `node_modules`: leave it in `dependencies` and note it in your report.

**Verify**: `pnpm install && pnpm build:ui` → exit 0; open `packages/ui/dist/vera-ui.css` head and confirm no raw `@import "@fontsource-variable/inter"` remains unresolved.

### Step 6: Add `sideEffects`

In `packages/ui/package.json`, add (top level, near `"files"`):

```json
  "sideEffects": ["**/*.css"]
```

Do **not** use `false` — `src/index.ts:3` imports CSS for its side effect, and `false` would let consumer bundlers drop all styles.

**Verify**: `pnpm build:ui` → exit 0; `node -e "const p=require('./packages/ui/package.json'); if(JSON.stringify(p.sideEffects)!==JSON.stringify(['**/*.css']))process.exit(1)"` → exit 0.

### Step 7: Remove `react-router-dom` from the root manifest

Delete the root `package.json` `dependencies` block (`react-router-dom` is already in `packages/ui` devDependencies + optional peer, and docs does not import it — confirm with `grep -rn "react-router-dom" packages/docs/app packages/docs/components packages/docs/lib` → if docs DOES import it, add it to `packages/docs/package.json` dependencies instead of just deleting).

**Verify**: `pnpm install` → exit 0; `pnpm dev:ui` starts without a missing-module error (Ctrl-C after it serves); `pnpm build:ui` → exit 0.

### Step 8: Consumer smoke test (pack + install)

```bash
cd packages/ui && pnpm pack --pack-destination /tmp/vera-pack
mkdir -p /tmp/vera-consumer && cd /tmp/vera-consumer && npm init -y >/dev/null
npm install react react-dom /tmp/vera-pack/helgadigitals-vera-ui-*.tgz
node -e "const m = require('@helgadigitals/vera-ui'); console.log(typeof m.Button)"
```

**Verify**: last command prints `function` (or `object` for a forwardRef) — the package resolves with only react/react-dom plus its own declared deps. Also check install size sanity: `du -sh /tmp/vera-consumer/node_modules` and record the number in your report (expect a large drop vs. before; you can measure "before" the same way from a clean checkout if asked, but recording "after" alone is acceptable).
